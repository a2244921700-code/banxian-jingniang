# 卦案与跨会话记忆

凡涉时辰、应期、方位，先调 `gua_now` 取时取地；卦案里的时间一律以它为准。

## 一、先取时取地

每次起卦前先调 `gua_now`：取准确时间、农历干支、真太阳时与方位。卦案的时间与应期都以此为准；定位失败时记「定位失败」，不要编经纬度。

## 二、记录：一卦一案

起盘（`gua_cast` / `gua_qimen` / `gua_liuren`）后即调 `gua_case`，`action: record`：

| 字段 | 填法 |
| question | 用户原话，不润色、不概括；有歧义先澄清再录 |
| method | 起卦法：梅花时间/数字/物数、六爻摇钱、奇门、六壬 |
| ben / bian | 本卦名与动爻、变卦名；奇门六壬写盘名，如「奇门·阴遁五局」「六壬·贼克课」 |
| judgment | 一句断语，须与答复里那句一致，便于日后对照 |
| keyPoints | 三至六条断卦依据（体用、用神旺衰、门星神、四课三传） |
| tags | 标签数组，按 §三 约定 |
| followUpAt | 应期 ISO 日期（如 2026-11-08）；用户主动提复盘时用 |

原则：断语必须在起卦当次写下，不许应验后补写；盘面只录盘上真有的字段，没给的就留空，不猜。

## 三、标签约定（便于检索）

- 事类：`工作` `钱财` `婚恋` `健康` `出行` `考试` `房宅` `官非` `寻物` `网络` `器物` `虚拟资产`
- 应期：`应期·日` `应期·月` `应期·年`
- 结果：`已验` `未验` `反验`
- 方法：`梅花` `六爻` `奇门` `六壬`

标签不超过五个，先事类后其余；同一卦只建一案，不重复录。

## 四、查旧卦：先档案，后会话

1. 先 `gua_case`，`action: list`，可用 `query`（关键词）、`tag`、`limit`。问「上次问工作那卦」就用 `tag:"工作"`。
2. 档案没有，再查本工作区会话：`gua_history`，`action: search_sessions`（给 `query`）或 `action: list_sessions`；命中后用 `action: read_session`（`sessionId` 必填，可给 `offset`、`maxChars` 翻页）。
3. 只读未归档会话：`includeArchived` 默认 false，不要改成 true 去翻归档；子代理会话已被过滤，本就不是给人看的。

## 五、复盘：用户回来或应验后 update

`gua_case`，`action: update`，必给 `caseId`：
- `outcome`：实际发生了什么，一两句，写事实不写评价。
- `note`：复盘——断对在哪一环、错在哪一环（用神取错？旺衰看错？应期取错？）。
- `verified: true` 表示已应验；反验则在 `note` 写明，并把标签改 `反验`。

复盘是长本事的地方：同一个环节连错三卦，就把「此环节易错」写进 note，下次断卦先查。

## 六、不许编造旧卦（硬规则）

1. 没读到档案与会话，不说「上次那卦」「你之前问过」。
2. 说「我查一下」→ 真调工具 → 查不到就明说「档案里没有，工作区里也没搜到」，请用户补一句问事或时间。
3. 只引用读到的原文；卦名、动爻、日期一律照抄，不凭印象补全。
4. 用户记忆与档案冲突时，以档案为准并问清：「档案记的是……，与你说的不同，以哪个为准？」
5. 绝不把本卦与别的卦混成「好像有这么一卦」；宁可说不知道。

## 七、隐私与边界

卦案里不写身份证号、电话、住址门牌、真实姓名（写「问卦人」即可）。会话只读，绝不写入或改动；知识库与卦案文件只经对应工具读写，不手改路径下的文件。
